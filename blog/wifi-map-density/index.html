When a Denser WiFi Map Gives Worse Answers

A fingerprint map grew from 1,022 to 4,852 synthetic points and matched fewer queries. The old points weren't better; they claimed to hear all 1,045 APs. Three ways to densify a map, and the error each brings.

更新于 2026/11/6 · 10 个章节
#WiFi#fingerprint maps#Gaussian processes#position uncertainty#multimodal positioning

An old Gaussian-process experiment grew the synthetic part of a WiFi fingerprint map from 1,022 to 4,852 entries, and the share of queries matching a synthetic neighbor dropped sharply. More map, fewer hits. What happened?

The answer was in the AP columns. Before a fix, every synthetic fingerprint had a value for all 1,045 APs in the building. After the fix, APs with no local observations to support them went back to being missing. Those easy-to-match synthetic points had been universal neighbors: places where, according to the map, you could hear every access point in the building. The hit rate fell because a data-semantics bug got fixed, not because the map got denser or sparser.

A later study did things more carefully. It labeled existing scans from continuous Motion trajectories, carried the label uncertainty explicitly and evaluated with a whole Trial held out. Its first fold failed in a different way: it picked the wrong floor with a mode mass close to 1.

These two results expose assumptions at opposite ends of the pipeline, one in the map inputs and one in the evaluation. In this post we’ll start by separating three things people mean by “a denser map.” We’ll unpack the universal-neighbor bug, then follow how label errors travel from a trajectory into a radio field and why they don’t average out. We’ll look at two query-side pitfalls (grid points that represent area, and peaks that shouldn’t be merged), go through the held-out fold, and finish with an experiment design that could actually tell these mechanisms apart.

Three ways to make a map denser

A point in a fingerprint map can come from at least three places, and they’re not interchangeable:

Source of the pointWhat it addsWhat it doesn’t automatically bring
A scan actually collected at a new locationNew RSS observations and detection eventsAn exact position label, or error independent of old data
Coordinates added to an existing continuous scanReal RSS that was unusable before now gets a position interpretationA new field observation, or a correct path shape
A grid point predicted by GP, interpolation or a generative modelAnother expression of existing observations and priorsA new independent measurement, or verified spatial coverage

All three make the database bigger, but they solve different problems. A new scan with an accurate label fills a blind spot directly. Splitting one offset trajectory into a hundred labels copies the same error a hundred times. Sampling an already-fitted field more finely mostly improves the numerical approximation.

Figure 1: A constructed sketch. The curved error in the middle and the grid on the right aren’t a real site; they illustrate labels inheriting the motion’s shape and predicted points inheriting an existing model.

This project chose the second route: label existing continuous scans via Motion and position references, then fit a field model. That puts the labels’ common error directly into the map inputs, and most of this post is about what that does.

Lesson 1: the universal neighbor

Back to the old experiment. In the old WiFi-map report, the bug was in missing-value semantics. That old format stored signal strength as positive values and used 100 to mean missing. So 100 isn’t a real weak signal, and the report’s 93 and 96 can’t be read as positive dBm measurements either.

If a local training group has almost no observations of some AP, but the missing sentinels from other rows go into the regression anyway, the model produces plausible-looking predictions in columns where there’s no information at all. Add uniform clipping, variance aggregation and a validity check on synthetic rows, and you can end up with every AP filled in. The saved coverage statistics show exactly that:

Historical versionSynthetic rowsMedian non-missing APs per rowRange
Before fix, two local regions1,0221,0451,045–1,045
After fix, full-floor candidate range4,852815–203

The fix had four parts. Each local group and each AP must have enough real observations to be fitted. Only rows where that AP actually appeared are used. Normalization is per column, from real observations. And the prediction check is applied only to supported columns. A global AP-frequency filter can’t replace this local check: an AP can be common across the building and never heard once in this particular corridor.

That historical fix also changed training iterations, candidate range, numeric precision and several stability settings, so the results below are not a “just add density” ablation:

That supports the historical observation that the old augmented database was broken and these known queries improved once it was fixed. It doesn’t support “GP improves positioning on unseen routes.” The report is explicit that the database was used as-is, without excluding each query’s own map-building sources by log or Trial, and the raw per-query results weren’t recovered this time. These numbers describe in-sample change on known queries.

One more issue hides behind “it runs now.” To equalize per-AP training lengths, the historical batch code duplicated observation rows with tiny coordinate jitter, alongside noise floors, jitter and double precision to dodge factorization failures. Those tricks help numerical stability, but duplicating an observation doesn’t create a second independent one. If duplicated rows are treated as independent likelihood terms, the statistical weighting has changed. There’s no ablation controlling the duplicate weight, so “missing sentinels no longer enter training” and “all statistical semantics are now correct” have to be judged separately.

Lesson 2: labels inherit the trajectory’s errors

Two anchors fix the ends, not the middle

The old labeler aligned a same-floor stretch of Radio-free Motion trajectory to two POSI reference points. With Motion end-points m0,m1m_0,m_1m0​,m1​ and reference end-points a0,a1a_0,a_1a0​,a1​, it used a 2D similarity transform:

x^t=a0+sR(mt−m0),s=∥a1−a0∥∥m1−m0∥.\hat x_t=a_0+sR(m_t-m_0),\qquad s=\frac{\|a_1-a_0\|}{\|m_1-m_0\|}.x^t​=a0​+sR(mt​−m0​),s=∥m1​−m0​∥∥a1​−a0​∥​.

RRR rotates the Motion end-to-end direction onto the reference direction. As long as neither baseline is degenerate, both end-points align exactly. Global translation, rotation and uniform scale errors are all removed. Heading errors that vary along the way, local scale changes and wrongly turned corners are not.

The existing _similarity function rejects end-point baselines under 1 m and scale ratios outside [0.25,4][0.25,4][0.25,4]. Those checks block some degenerate inputs, but they can’t show that the middle of a trajectory that passes them is right. A back-and-forth path can cover a long distance with start and end close together, so the end-point displacement doesn’t pin down a stable similarity transform in the first place.

Here’s a deliberately constructed counterexample, run through the frozen _similarity itself. The true path is a straight 20 m line, the Motion path bulges out 5 m halfway, and both end-points are exact. After the transform, end-point error is below 10−1210^{-12}10−12 m, and the midpoint error is still 5 m.

Figure 2: A constructed mechanism experiment, not a 5 m error extracted from a real trajectory.

It exposes the old method’s key assumption: between anchors, the path shape comes mostly from Motion, and end-point residuals can’t test that shape. The old handoff report also records the two-end similarity transform disagreeing clearly with another position reference on an outdoor stretch. No re-aggregatable raw comparison survives, though, so the report’s magnitude can’t identify which sensor caused it, and an outdoor result can’t be generalized to every indoor interval.

The newer labeler therefore uses multiple reference points to constrain translation, piecewise heading and scale together, and estimates local parameter uncertainty. It checks convergence, rank, anchor residuals and label standard deviation. Scans outside actual Motion coverage, in gap intervals, on unknown floors or failing conditions can stay unlabeled, rather than being filled in by copying end-point coordinates.

“More anchors” still doesn’t recover the original inertial model’s joint posterior, though. The old Motion cache didn’t save the full TLIO joint covariance. The current labeler uses a local Gauss–Newton/Laplace approximation plus an extra bridge process, marked in the code as a development approximation. That limitation should travel with the labels into the map, rather than disappearing when a nice trajectory figure is exported.

Shared label error doesn’t average out

Now the statistical consequence. Suppose label errors along one trajectory come from shared parameters plus local error:

δxi=Jiδθ+ηi,Cov⁡(δxi,δxj)=JiΣθJj⊤+Cov⁡(ηi,ηj).\delta x_i=J_i\delta\theta+\eta_i,\qquad \operatorname{Cov}(\delta x_i,\delta x_j) =J_i\Sigma_\theta J_j^\top+ \operatorname{Cov}(\eta_i,\eta_j).δxi​=Ji​δθ+ηi​,Cov(δxi​,δxj​)=Ji​Σθ​Jj⊤​+Cov(ηi​,ηj​).

Here the shared parameters are assumed uncorrelated with local error, and JiJ_iJi​ describes how one heading, scale or translation parameter affects coordinate iii. Even if every point stores its own 2×22\times22×2 covariance, dropping the cross-point term lets the map fitter treat a common error as independent noise that averages away.

It’s zero at both ends and allows deviation in the middle. This is the current modeling choice for residual path error, not the true inertial joint covariance read from the cache. The code also checks that the shared term doesn’t exceed each point’s declared total covariance, so the same uncertainty isn’t counted twice.

If the shared bias is treated as a fixed unknown rather than a random variable, the formula should be read as a mean squared error including a bias term.

With shared error, a hundred scans buy you almost nothing over ten: the floor is 3 dB no matter what. “More scans” doesn’t automatically mean “information grows with the count.” Observations from an independent trajectory, another time or another direction can be worth more than further densifying the same offset path.

From noisy labels to a radio field

With labels in hand, the map models, for each AP aaa, the signal when it’s heard:

yi=fa(xi)+ϵi.y_i=f_a(x_i)+\epsilon_i.yi​=fa​(xi​)+ϵi​.

The current local field uses an RBF kernel on physical coordinates, optionally multiplied by an RBF kernel on map-region features:

k(x,z)=σf2exp⁡ ⁣[−∥x−z∥22ℓ2−∥ϕ(x)−ϕ(z)∥22ℓϕ2].k(x,z)=\sigma_f^2 \exp\!\left[-\frac{\|x-z\|^2}{2\ell^2} -\frac{\|\phi(x)-\phi(z)\|^2}{2\ell_\phi^2}\right].k(x,z)=σf2​exp[−2ℓ2∥x−z∥2​−2ℓϕ2​∥ϕ(x)−ϕ(z)∥2​].

Without region features, drop the second term. This construction keeps the kernel positive semidefinite, but region features aren’t true geodesic distance, and walls don’t become perfectly opaque boundaries.

With label error included, the fitting matrix is approximately

Q=K+σϵ2I+Ω,Q=K+\sigma_\epsilon^2I+\Omega,Q=K+σϵ2​I+Ω,

and the predictive mean and latent-field variance are

m∗=yˉ+k∗⊤Q−1(y−yˉ1),vlatent,∗=k∗∗−k∗⊤Q−1k∗.m_*=\bar y+k_*^\top Q^{-1}(y-\bar y\mathbf1),\qquad v_{\mathrm{latent},*}=k_{**}-k_*^\top Q^{-1}k_*.m∗​=yˉ​+k∗⊤​Q−1(y−yˉ​1),vlatent,∗​=k∗∗​−k∗⊤​Q−1k∗​.

Here yˉ\bar yyˉ​ is the code’s local constant baseline (the median observed RSS), not a separately fitted spatial trend. A few honest caveats about the implementation:

  • It fits once ignoring position noise, estimates gradients, then adds Ω\OmegaΩ and solves again. It doesn’t integrate exactly over uncertain coordinates or iterate to a joint optimum of coordinates and field.
  • The exported RSS predictive variance includes measurement noise, so it isn’t the pure latent-field variance; the query stage adds a separately declared query noise.

📝 Further reading: An Online Radio Map Update Scheme for WiFi Fingerprint-Based Localization already propagates position uncertainty through first-order gradients in its Eqs. (6) and (10)–(12). I borrow the mechanism, not its online system. The paper also has hyperparameter particles and time-varying field updates that the local GP doesn’t implement, and its position-uncertainty experiments use a simplified independent isotropic assumption, so it can’t calibrate the shared label covariance here.

Predicted grid points also need to keep their provenance: which real scans support them, how far the nearest support is, which APs have models and whether this is a measured or predicted region. Exporting the GP mean as a new training sample “equivalent to a real scan” and feeding it back into the same model counts the model’s own assumptions twice. A fine grid is a fine storage format for a field, but a format change doesn’t create new observations.

Querying the map

A query needs more than an RSS vector distance. With DaD_aDa​ indicating whether this scan detected AP aaa, at least separate

P(Da=1∣x)=da(x),p(ya∣Da=1,x).P(D_a=1\mid x)=d_a(x), \qquad p(y_a\mid D_a=1,x).P(Da​=1∣x)=da​(x),p(ya​∣Da​=1,x).

If the AP was heard, use the conditional signal distribution and the detection probability. If it wasn’t, use 1−da(x)1-d_a(x)1−da​(x) instead of filling in a fake RSS. And where there isn’t enough local data to model an AP at all, a validity mask has to say “no model here,” which is different from “the model says the signal is weak here.” (That’s exactly the distinction the universal-neighbor bug got wrong.)

The current query is organized around those three objects: conditional RSS mean/variance, detection probability and model validity mask. Positions without a model use a finite zero placeholder that’s explicitly masked out, so no NaN or sentinel leaks into the distance.

The score for observed APs is approximately

ℓiobs=τo∑a∈O[log⁡N(ya;μia,via+σq2)+log⁡dia],\ell_i^{\mathrm{obs}} =\tau_o\sum_{a\in O} \left[\log \mathcal N(y_a;\mu_{ia},v_{ia}+\sigma_q^2) +\log d_{ia}\right],ℓiobs​=τo​a∈O∑​[logN(ya​;μia​,via​+σq2​)+logdia​],

plus a detection term for unobserved APs:

ℓiabs=τm∑a∉Olog⁡(1−dia).\ell_i^{\mathrm{abs}} =\tau_m\sum_{a\notin O}\log(1-d_{ia}).ℓiabs​=τm​a∈/O∑​log(1−dia​).

For a known AP with no valid model at some position, the code substitutes a wide background distribution and a small detection probability. Inputs entirely outside the map’s AP dictionary go into diagnostics like a known-fraction count, but don’t get a local conditional model.

APs can be co-located, share hardware or share a propagation environment, so the code tempers the observed and absent terms separately, with defaults τo=min⁡(1,12/∣O∣)\tau_o=\min(1,12/|O|)τo​=min(1,12/∣O∣) and τm=min⁡(1,4/∣Oc∣)\tau_m=\min(1,4/|O^c|)τm​=min(1,4/∣Oc∣). The second term is only computed when there are unobserved APs. This is a development-stage composite-likelihood policy, not an estimated joint distribution between APs, and the defaults weren’t tuned on the first-fold results.

The map also needs a NULL hypothesis: the input might not belong to any region the map supports. The current implementation builds it from a wide RSS background, an area-weighted background detection rate and an explicit NULL prior. Being able to keep NULL mass is a gain in expressiveness; whether NULL values are calibrated is a separate question for held-out data.

Grid points represent area

Here’s a pitfall that’s easy to miss. Two corridors, left and right, each 1 m², give exactly the same likelihood for the current scan. The left one is stored as 100 rows, the right as 1. With equal prior per row, the left gets probability 100/101100/101100/101. Nothing about the position or the observation changed, only how the file samples space, and the answer swings left.

Probability mass in continuous space integrates over area. With a grid approximation, weight by the area ΔAi\Delta A_iΔAi​ each point represents:

wi∝(1−πNULL)exp⁡(ℓi)ΔAi∑j∈activeΔAj,wNULL∝πNULLexp⁡(ℓNULL).w_i\propto (1-\pi_{\mathrm{NULL}}) \exp(\ell_i) \frac{\Delta A_i}{\sum_{j\in\mathrm{active}}\Delta A_j}, \qquad w_{\mathrm{NULL}}\propto \pi_{\mathrm{NULL}}\exp(\ell_{\mathrm{NULL}}).wi​∝(1−πNULL​)exp(ℓi​)∑j∈active​ΔAj​ΔAi​​,wNULL​∝πNULL​exp(ℓNULL​).

The current query normalizes by area over the active candidate region. That has conditions too: it allocates the non-NULL prior over the current active support, without inferring the true area of unmodeled regions or the probability of an unknown location. Change the active support and the answer can still change.

The frozen query module was tested on exactly this property. Two constructed regions 20 m apart share the same three AP models. The left one is duplicated into 1, 2, 4, 10, 50 and 100 rows, with each row’s area set to 1/n1/n1/n; the right one keeps area 1. Both peaks are kept every time.

Figure 4: Left-region probability as rows are duplicated, under area weighting vs. equal weighting per row.

At 100 duplicate rows, the area scheme still gives the left region a conditional probability of 0.500000; equal-per-row weighting gives 0.990099. The area scheme’s NULL probability is 0.000424657, which is just what these constructed means, variances and default priors produce. It isn’t a field rejection threshold.

The test deliberately makes duplicate rows identical in coordinates and likelihood, changing only representation, so it verifies that integration weights aren’t distorted by repetition. A real finer grid changes sample locations, predictions and how peaks connect, so finite-grid results aren’t guaranteed identical; convergence of the integral and mode segmentation need separate checks.

Keep separate peaks separate

Even a correctly normalized grid posterior can’t always be collapsed to one position. Take a 1D position distribution

p(x)=12N(x;−10,1)+12N(x;10,1).p(x)=\tfrac12\mathcal N(x;-10,1) +\tfrac12\mathcal N(x;10,1).p(x)=21​N(x;−10,1)+21​N(x;10,1).

Its mean is zero, which sits in the low-density gap between the two explanations:

p(0)p(10)=2e−501+e−200≈3.86×10−22.\frac{p(0)}{p(10)} =\frac{2e^{-50}}{1+e^{-200}} \approx3.86\times10^{-22}.p(10)p(0)​=1+e−2002e−50​≈3.86×10−22.

The true variance is 1+102=1011+10^2=1011+102=101. Keeping only the within-peak variance of 1 misses the cross-peak ambiguity. Keeping mean 0 and total variance 101 gets the second moment right but still loses the fact that the two corridors are far apart. Behind walls, on different floors or in disconnected spaces, the mean may not even be somewhere a person can stand.

The current code forms peaks by floor and by ascending local density, instead of merging points on one connected grid into a single answer. Each peak keeps its mass, position, covariance and provenance, and NULL and small peaks aren’t dropped. That fixes the output representation. Peak-connection radius, grid resolution and AP models still affect the result, and keeping multiple peaks doesn’t remove wrong ones.

Likewise, normalized inverse-distance WKNN weights don’t automatically become a position posterior. Even with an explicitly normalized composite likelihood, a weak background model, skewed floor coverage or mishandled AP correlation can let a wrong mode take nearly all the mass. The saved first fold is exactly that counterexample.

Look at the first saved query. The true floor is 2, and both models chose floor 3. A’s selected mode mass is about 0.999489 with horizontal error 26.166 m; B’s is about 0.999999918 with 23.921 m. That’s enough to refute “close to 1 after normalization means the position is reliable.” It doesn’t tell us whether labels, coverage, the floor prior or the likelihood is to blame.

B has one number that’s easy to misuse. In auxiliary queries with the floor forced to be correct, its saved mean horizontal error is about 6.179 m. That’s conditional on extra knowledge of the floor, and it covers only the 11 auxiliary queries that produced an accepted result; it isn’t online error. A has no usable result under that metric, which can’t be filled in as zero or paired against B.

The effective training sources also differ. A ended up with only eight logs from Trials 31 and 34; B added Trial25, for twelve. The other allowed training sources didn’t automatically become valid labels. So nothing about B’s results can be credited to “11 more grid points.”

The biggest gap is C and D. With no saved held-out GP evaluation, there’s no basis to say the new GP densification beats the measured grid. The code can express shared covariance, predictive variance and NULL; that just makes the next experiment more likely to answer the question.

Designing a comparison that can tell mechanisms apart

📝 Further reading: Malikov et al.’s When Data Augmentation Falls Short compares a tuned non-augmented baseline against five families of generative models. On its UTS subset (522 fingerprints, 198 reference locations), with 70% of locations omitted, non-augmented kNN gets 5.93 m in Table 3 and the best augmentation 6.84 m. Even more important is Appendix B: the original set has many duplicate RSS vectors, and at 0% omission 57 of 105 test samples have a zero-distance fingerprint in training. So excellent dense-end scores can’t be read as generalization to new locations, and the paper doesn’t show “generative augmentation never helps” either.

The direct lesson for this project is experimental design. Tune the measured baseline properly on a development set; hold out whole collection routes, devices or spatial regions together; then ask whether augmentation’s gain survives. Don’t fully tune the augmentation method and pit it against a default-parameter WKNN. Finishing the original A/B/C/D held-out design is the obvious next step, and it has to control four stages in order:

  1. Sources. Hold out whole Trials, counting different devices and sessions on the same route together, so near-duplicate scans of one path don’t straddle the split. Device hold-out answers device transfer and spatial hold-out answers blind-spot prediction; Trial hold-out can’t substitute for either. Spatial hold-out also has to delete raw scans in time intervals adjacent to hidden anchors, so relabeled positions can’t drift out of the excluded zone while their raw RSS flows back into training.
  2. Labels. Report which scans were accepted, rejected or left unlabeled, and whether rejections cluster on certain floors, turns or long intervals. Comparing final error without reporting which hard samples were dropped can mistake shrinking coverage for better accuracy. Continuously labeled trajectories also can’t serve as their own dense ground truth.
  3. Field model. Separate B→C interpolation gains, gains from propagating position error, and C→D region-feature gains. The plan included a C variant with position-uncertainty propagation turned off; it wasn’t run. Grid spacing changes should be compared on the same collected data, physical region and consistent area prior, reporting true support distance rather than a smooth full-coverage heatmap.
  4. Queries. Report horizontal error, wrong floor, large tail errors, rejection rate and NULL side by side. RSS RMSE, predictive interval coverage and Brier scores for detection probability help explain whether the field is reasonable, but they can’t replace position error. A wide RSS interval can get great coverage. Confidence should be checked grouped by Trial or collection cluster, not by treating consecutive scans as independent samples to manufacture narrow error bars.

Navigation comes last. Once map, version and query policy are frozen, check asynchronous scheduling, trajectory feedback and evidence reuse separately. A more accurate offline map doesn’t license the online system to reuse the same scans as new constraints across windows. My work stops at read-only map queries; navigation experiments that weren’t run aren’t reported as done.

What this does and doesn’t show

  • It shows that the old “universal neighbor” came from missing APs being filled in (median 1,045 APs per synthetic row before the fix, 81 after).
  • It shows, with constructed inputs run through frozen project code, that two exact anchors can leave a 5 m mid-path error, that shared label error puts a floor under uncertainty, and that area weighting keeps duplicated rows from shifting region probability.
  • It shows that on the first held-out fold, both A and B mostly pick the wrong floor, sometimes with mode mass above 0.9999.
  • The old GP results are in-sample on known queries, with other settings changed at the same time and raw per-query results lost.
  • There are no saved C/D results, so nothing here says GP prediction or region features improve positioning.
  • No GP was trained, no 72-log maps were rebuilt and no navigation was run; the first fold also predates five module changes in the final code.

Conclusion

Let’s recap. “A denser map” can mean new scans, new labels on old scans or predicted points, and only the first adds independent observations. The old GP’s extra points were universal neighbors because missing values were filled in. The newer labels inherit their trajectory’s shape and shared error, which doesn’t average away. On the query side, grid points stand for area, separate peaks need to stay separate, and a normalized mode mass near 1 can still sit on the wrong floor. Explaining that wrong floor and completing the paired comparison should come before generating candidate maps for all 72 logs.

A map gets better when it learns something new about the building, not just when the file gets longer.
